# Viewport contract — `make_view(w, h)` (1A / X-H1)

## Contract

`make_view` is `FnMut(w: u32, h: u32) -> (VNode, Stylesheet)` where
`(w, h)` are **logical viewport dimensions** in CSS pixels:

```
logical = Viewport::from_i32(physical_w, physical_h, scale_factor).logical_size()
// physical = (logical * scale).round(); single rounding point is Viewport
```

The renderer calls `make_view` with the *current* logical `w,h`:

* once on startup (initial frame before the event loop),
* on every `RedrawRequested` after a `WindowEvent::Resized` / `ScaleFactorChanged`.

See `velox-renderer/src/lib.rs` — `run_window_vnode_skia` and
`run_window_vnode_skia_with_hmr` (rustdoc on those fns is the
authoritative contract).

## Why it matters (Flutter invariant)

Layout is viewport-driven: `compute_layout(&vnode, w as i32, h as i32)`.
If `make_view` ignores `w,h` (`|_w,_h|`) the app is non-responsive — resize
has no visible effect and elements hide when they should be visible.
After 1A the app follows the Flutter invariant: it survives any window
size including 0×0 → restore, rapid drag, fractional DPI, minimize/maximize
with no hidden-when-visible element.

## Template obligation

All shipped templates (`velox-cli/templates/project/`, `examples/counter/`,
`examples/todo/`, and any project created via `velox init` / `velox-cli::build_cmd`)
must:

1. **Acknowledge `(w,h)`** — do not discard them:
   ```rust
   // ❌ wrong
   move |_w: u32, _h: u32| -> (VNode, Stylesheet) { ... }
   // ✅ correct
   move |w: u32, h: u32| -> (VNode, Stylesheet) {
       let _viewport = (w, h);
       // ... render_with_state, Stylesheet::parse ...
   }
   ```
   All templates now bind `w,h` and keep `let _viewport = (w,h);` so clippy
   and future audits visibly track the contract (also a hook for future
   viewport-aware rendering).

2. **Use a viewport-filling root** so `compute_layout` actually reflows.
   The canonical pattern is on the root `.app`:

   ```css
   .app {
     width: 100%;
     min-height: 100vh;
     /* display/flex per template varies */
   }
   ```

   `width:100%` makes the root span the viewport width; `min-height:100vh`
   pins it to at least the viewport height (not `height:100%` which
   over-constrains flex children). `velox-dom` already treats `min-height:100vh`
   and `width:100% × height:100%` as viewport-filling and maps them to the
   `avail_w/h` of `compute_layout` (see `layout.rs` viewport-height handling).
   Every shipped `App.vx` now carries this (`velox-cli/templates/project/src/App.vx`,
   `examples/counter/src/App.vx`, `examples/todo/src/App.vx`, and the
   strings generated by `velox-cli/src/commands/init.rs` `generate_app_vx` /
   `init_app`).

## Verification (manual + automated)

* **Repro tests** — `velox-cli/tests/template_w_h_repro.rs` (string checks
  that no `|_w` discard remains, root has `width:100%`/`min-height:100vh`,
  renderer docs mention viewport) and
  `velox-dom/tests/template_w_h_layout_repro.rs` (simulated screenshot
  maximized vs 400×300: compute_layout must yield larger `rect.w` for larger
  viewport and must not hide the 50%-width child). Both must be green before
  merging 1A.
* **Manual drag-resize** — `cargo run --example todo` (or any `cargo run`),
  drag-resize window arbitrary; root visibly fills, no clipping/hidden child;
  compare maximized vs 400×300 (simulated via the layout test).
* **DPI** — fractional `wlr-randr --scale 1.25` still reflows because logical
  `w,h` are always `Viewport`-derived single-rounding.

## Renderer docs

The rustdoc on `run_window_vnode_skia` / `run_window_vnode_skia_with_hmr`
repeats this contract so IDE hover and `cargo doc` surface it next to the
type `F: FnMut(u32,u32) -> (VNode, Stylesheet)`.
